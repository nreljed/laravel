# Cost Breaker 360

A SaaS application for cost management built with Laravel + Inertia.js + React 19.

## Requirements

- PHP 8.3+ (8.4 recommended)
- Composer 2.x
- Node.js 22+
- MySQL 8.0+ (production) or SQLite (local development)

## First-Time Setup

```bash
# 1. Install PHP dependencies
composer install

# 2. Install frontend dependencies
npm install

# 3. Create environment file and generate app key
cp .env.example .env
php artisan key:generate

# 4. Configure database
#    By default SQLite is used (database/database.sqlite).
#    For MySQL, edit .env and uncomment the DB_* lines:
#      DB_CONNECTION=mysql
#      DB_HOST=127.0.0.1
#      DB_PORT=3306
#      DB_DATABASE=your_database
#      DB_USERNAME=your_user
#      DB_PASSWORD=your_password

# 5. Run migrations and seeders
php artisan migrate
php artisan db:seed --class=RolesAndPermissionsSeeder

# 6. Sync module permissions
php artisan modules:sync-permissions

# 7. Create storage link
php artisan storage:link

# 8. Start development servers (two terminals)
npm run dev     # Vite HMR at localhost:5173
php artisan serve  # Laravel at localhost:8000
```

Open `http://localhost:8000` and register a new account, or use the seed scripts:

```bash
# Seed test users (admin + regular user)
php artisan db:seed --class=DatabaseSeeder
# Or manually:
php scripts/seed-test-users.php
```

## Environment Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `APP_NAME` | `Laravel` | Site name used in emails, page titles, etc. |
| `APP_URL` | `http://localhost` | Must match the deployment URL for proper Vite asset resolution |
| `APP_ENV` | `local` | Set to `production` on live server |
| `APP_DEBUG` | `true` | Set to `false` in production |
| `APP_KEY` | — | Auto-generated by `php artisan key:generate` |
| `DB_CONNECTION` | `sqlite` | `sqlite` for local, `mysql` for production |
| `SESSION_DRIVER` | `database` | Uses `sessions` table; switch to `file` or `redis` for high traffic |
| `CACHE_STORE` | `database` | Uses `cache` table; switch to `redis` for high traffic |
| `QUEUE_CONNECTION` | `database` | Uses `jobs` table; switch to `redis` for async queue workers |
| `MAIL_MAILER` | `log` | `log` writes to `storage/logs/laravel.log`; use `smtp` for real email delivery |
| `MAIL_HOST` | `127.0.0.1` | SMTP host (required for `smtp` mailer) |
| `MAIL_PORT` | `2525` | SMTP port |
| `MAIL_USERNAME` | — | SMTP username |
| `MAIL_PASSWORD` | — | SMTP password |
| `MAIL_FROM_ADDRESS` | `hello@example.com` | "From" address for all outgoing emails |
| `MAIL_FROM_NAME` | `${APP_NAME}` | "From" name for outgoing emails |
| `DEPLOY_TOKEN` | — | Must match `DEPLOY_TOKEN` GitHub secret for auto-deploy |

## Rate Limiting

| Action | Limit | Response | Mechanism |
|--------|-------|----------|-----------|
| Login | 5 attempts per `{username}\|{ip}` key, 60s decay per hit | HTTP 422 with error message | `LoginRequest::ensureIsNotRateLimited()` |
| Register | 5 per 60 min per IP | HTTP 429 | Route middleware `throttle:5,60` |
| Forgot password | 5 per 60 min per IP | HTTP 429 | Route middleware `throttle:5,60` |
| Reset password | 5 per 60 min per IP | HTTP 429 | Route middleware `throttle:5,60` |

Login uses an application-level `RateLimiter` (per-user + IP, resets on success, shows remaining time). All other auth endpoints use Laravel's route `throttle` middleware. Both store counters in the `cache` table — counters reset automatically after `migrate:fresh`.

## Roles

- **admin** — Full access. Created via scripts only (cannot register as admin).
- **crm_user** — Default role for new registrations. Configurable in Settings > Registration.

## Host/Guest Mode

Users with the `bookings.view` permission can switch between **Host** and **Guest** modes. The current mode is stored in session and displayed in the user dropdown. Use the toggle in the nav-user dropdown to switch.

- **Host mode**: Full property booking management (requires applicable permissions).
- **Guest mode**: Limited browsing view (default for new users).

## Module System

Pluggable feature modules live in `app/Modules/`. Each module can register routes, permissions, and UI components.

| Module | Description |
|--------|-------------|
| Booking | Property booking management |
| Properties | Property CRUD and management |
| Shop | Online store functionality |

Enable/disable modules via the admin dashboard (requires admin role).

## Development Commands

```bash
npm run dev              # Vite dev server with HMR
npm run build            # tsc + vite build (production)
php artisan migrate      # Run pending migrations
php artisan test         # Run PHPUnit tests
npm run typecheck        # TypeScript type checking (tsc --noEmit)
vendor/bin/pint          # Laravel Pint (PSR-12 linting + auto-fix)
php artisan db:seed --class=RolesAndPermissionsSeeder  # Reset roles/permissions
php artisan modules:sync-permissions                   # Sync module permissions
php artisan app:create-admin                           # Bootstrap or update the admin user
```

## Project Structure

```
app/
  Http/Controllers/       # Laravel controllers
  Http/Middleware/         # HandleInertiaRequests (shares auth, notifications, mode, flash)
  Models/                  # Eloquent models (User, Role, Permission, Setting)
  Services/                # Business logic (AccountService, SettingsService, NotificationService)
  Modules/                 # Feature modules (Booking, Properties, Shop)
database/
  migrations/              # Standard Laravel migrations
  seeders/                 # Seeders (roles, permissions, settings)
resources/js/
  Components/              # React components (shadcn/ui + custom)
  Pages/                   # Inertia page components
  Layouts/                 # Authenticated, Admin, Guest, Public layouts
routes/                    # Route definitions (web.php, auth.php, admin.php)
docs/                      # Feature documentation
scripts/                   # CLI utility scripts
```

## Key Features

- **Role-based access control**: Admin and CRM user roles with granular permissions
- **Host/Guest mode**: Session-based user mode switching with permission gates
- **Notification system**: Zero-infrastructure polling (20s intervals), database-only delivery
- **Settings management**: DB-driven app configuration (name, logo, URL, registration, email)
- **Module system**: Pluggable feature modules with permission auto-sync
- **Account management**: Profile editing, password change, account deletion with full data cleanup
- **Email**: SMTP configuration via admin panel with template simulation
- **Deployment**: CI/CD via GitHub Actions with auto-deploy endpoint
- **Dark mode**: Theme toggle via next-themes (light/dark/system)
