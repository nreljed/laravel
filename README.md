# Cost Breaker 360

A SaaS dashboard for cost management built with Laravel 13 + Inertia.js 3 + React 19.

## Architecture: platform consumer in a pnpm workspace

This repo is a **thin app shell + theme** on top of the shared `nreljed/platform`
product. The dashboard, admin panel, auth, account, notifications, settings, deploy
pipeline and the feature-provider layer all live in the platform package; content
features ship as sibling packages (`nreljed/blog`) and modules
(`nreljed/shop-module`, `nreljed/booking-module`).

- **PHP side (unchanged):** `nreljed/platform` + `nreljed/blog` are Composer vcs
  installs from GitHub into `vendor/`, pinned by `composer.lock` (the pin of
  record — commit it whenever packages update).
- **Frontend side (workspace era):** the repo root is a pnpm workspace. The
  frontend kits are consumed as workspace packages (`@nreljed/platform`,
  `@nreljed/blog`, …) symlinked from `node_modules` → `packages/*`, with a single
  root `pnpm-lock.yaml` as the npm pin of record. `apps/*` (laravel.shop,
  laravel.booking) are brought into the workspace too; the mono app itself stays
  at the root.
- **Never edit `vendor/` or `packages/*`** — package sources live in their own
  repos (`nreljed/platform`, `nreljed/blog`, `nreljed/shop-module`,
  `nreljed/booking-module`). Core changes go through PRs + semver tags in those
  repos; consumers pull via `composer update` / `pnpm install`.

See `AGENTS.md` for the full package model and workspace layout.

## Requirements

- PHP 8.4+
- Composer 2.x
- pnpm 11+
- Node.js 22+
- MySQL 8.0+ (production) or SQLite (local development)

## First-Time Setup

```bash
# 1. Install PHP dependencies (composer.lock pins platform + blog)
composer install

# 2. Install frontend dependencies (single root pnpm-lock.yaml)
pnpm install

# 3. Create environment file and generate app key
cp .env.example .env
php artisan key:generate

# 4. Configure database
#    By default SQLite is used (database/database.sqlite).
#    For MySQL, edit .env and uncomment the DB_* lines:
#      DB_CONNECTION=mysql
#      DB_HOST=127.0.0.1
#      DB_PORT=3306
#      DB_DATABASE=your_database
#      DB_USERNAME=your_user
#      DB_PASSWORD=your_password

# 5. Run migrations and seeders (roles/permissions are config-catalog driven)
php artisan migrate
php artisan db:seed --class=RolesAndPermissionsSeeder

# 6. Create storage link
php artisan storage:link

# 7. Start development servers (Run via LocalWP; Vite HMR)
npm run dev        # Vite dev server with HMR
php artisan serve  # Laravel at localhost:8000
```

> Note: the app is served via LocalWP and runs the **production build** (no Vite
> dev server). Verify `public/hot` does not exist — its presence causes
> `ERR_CONNECTION_REFUSED`. Always run `npm run build` after code changes.

## Environment Configuration

| Variable            | Default             | Description                                                          |
| ------------------- | ------------------- | -------------------------------------------------------------------- |
| `APP_NAME`          | `Cost Breaker 360`  | Site name used in emails, page titles, etc.                          |
| `APP_URL`           | `http://localhost`  | Must match the deployment URL for proper Vite asset resolution       |
| `APP_ENV`           | `local`             | Set to `production` on live server                                   |
| `APP_DEBUG`         | `true`              | Set to `false` in production                                         |
| `APP_KEY`           | —                   | Auto-generated by `php artisan key:generate`                         |
| `DB_CONNECTION`     | `sqlite`            | `sqlite` for local, `mysql` for production                           |
| `SESSION_DRIVER`    | `database`          | Uses `sessions` table; switch to `file` or `redis` for high traffic  |
| `CACHE_STORE`       | `database`          | Uses `cache` table; switch to `redis` for high traffic               |
| `QUEUE_CONNECTION`  | `database`          | Uses `jobs` table; switch to `redis` for async queue workers         |
| `MAIL_MAILER`       | `log`               | `log` writes to `storage/logs/laravel.log`; use `smtp` for real mail |
| `DEPLOY_TOKEN`      | —                   | Must match `DEPLOY_TOKEN` GitHub secret for auto-deploy              |

## Roles

- **admin** — Full access. Created via `app:create-admin` (cannot register as admin).
- **editor** — Default role for new registrations. Configurable in Settings > Registration.
- **author** — Content creation (no delete).
- **user** — Own profile + dashboard + notifications.

Roles and permissions are a config catalog (`config/roles.php`, per-app
overridable) seeded by `RolesAndPermissionsSeeder`. Custom slug-based RBAC —
package-owned models, not Spatie.

## Feature Architecture

Features are self-contained `FeatureProvider`s discovered by the platform's
`FeatureRegistry`. Each provider registers its own routes, permissions, nav
items, dashboard data and frontend pages.

| Feature | Slug    | Permissions                                                | Frontend Pages                           |
| ------- | ------- | ---------------------------------------------------------- | ---------------------------------------- |
| Blog    | `posts` | `posts.view`, `posts.create`, `posts.edit`, `posts.delete` | Index, Form, Dashboard, Categories, Tags |

NEW features ship as packages or `app/` domains wired through
`config/features.php` `providers` (see the feature-architecture skill /
platform docs).

## Development Commands

```bash
pnpm install             # workspace install (single root pnpm-lock.yaml)
npm run build            # tsc + vite build (production)
npm run dev              # Vite dev server with HMR
npm run typecheck        # TypeScript type checking (tsc --noEmit)
npm run lint             # ESLint
npm run format:check     # Prettier check
npm run test             # Vitest frontend tests
npm run check:ci         # Full CI pipeline (consistency + lint + typecheck + format + test + pint + phpunit)
composer install         # Install/update PHP deps (pins platform + blog)
php artisan migrate      # Run pending migrations
php artisan test         # Run PHPUnit tests
vendor/bin/pint          # Laravel Pint (PSR-12 auto-fix)
php artisan permissions:list             # List all permissions
php artisan db:seed --class=RolesAndPermissionsSeeder  # Reset roles/permissions
php artisan app:create-admin             # Bootstrap or update the admin user
```

Other useful commands: `php artisan test --parallel --compact` (parallel PHPUnit
via paratest), `npm run check:core-deps` / `npm run check:platform-consistency`
(drift guards).

## AI Integration (BYOK)

Pure Bring-Your-Own-Key — zero platform AI cost. Users manage their own API keys
via Account → AI Keys (encrypted storage, owner-only access). Agents
(`SeoAgent`, `ChatAgent`, `ContentAgent`) resolve the per-user provider
dynamically via `provider()`; supported providers: OpenAI, Anthropic, Gemini,
Mistral, DeepSeek, xAI (Grok), Ollama.

## Key Features

- **Role-based access control**: custom slug-based RBAC with granular permissions
- **Admin panel**: user/role/permission management, system health, audit logs, settings
- **Notification system**: database-channel notifications with preference-aware dispatch
- **Blog CMS**: posts, categories, tags, content blocks, scheduled publishing, SEO (AI)
- **Settings management**: DB-driven app configuration (name, logo, URL, registration, email, SMTP)
- **AI (BYOK)**: per-user provider keys, structured output, streaming chat assistant
- **Deployment**: zero-SSH CI/CD via GitHub Releases + token-protected endpoints
- **Dark mode**: theme toggle via next-themes (light/dark/system)
