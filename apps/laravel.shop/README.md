# Shop App

A SaaS e-commerce application built with Laravel 13 + Inertia.js 3 + React 19 — a
**thin consumer** of the `nreljed/platform` shared platform with the
`nreljed/blog` + `nreljed/shop-module` feature packages.

## Architecture: package consumer

- **PHP side:** `nreljed/platform`, `nreljed/blog` and `nreljed/shop-module`
  are Composer vcs installs from GitHub into `vendor/`, pinned by
  `composer.lock` (the pin of record — commit it whenever packages update).
- The dashboard, admin panel, auth, account, notifications, settings, deploy
  pipeline and the feature-provider layer all live in the platform package;
  blog (posts) and shop (products, orders, cart, storefront) features ship as
  packages.
- The host keeps only thin-shell wiring: `app/` (Models, Console, Providers),
  host-local dashboard/account components, public marketing templates in
  `resources/js/Pages/`, and the `page-config.ts` page map.
- **Never edit `vendor/`** — package sources live in their own repos
  (`nreljed/platform`, `nreljed/blog`, `nreljed/shop-module`). Changes go
  through PRs + semver tags there; consumers pull via `composer update`.

## Requirements

- PHP 8.4+
- Composer 2.x
- Node.js 22+
- MySQL 8.0+ (production) or SQLite (local development)

## First-Time Setup

```bash
# 1. Install PHP dependencies
composer install

# 2. Install frontend dependencies
npm install

# 3. Create environment file and generate app key
cp .env.example .env
php artisan key:generate

# 4. Configure database
#    By default SQLite is used (database/database.sqlite).
#    For MySQL, edit .env and uncomment the DB_* lines:
#      DB_CONNECTION=mysql
#      DB_HOST=127.0.0.1
#      DB_PORT=3306
#      DB_DATABASE=your_database
#      DB_USERNAME=your_user
#      DB_PASSWORD=your_password

# 5. Run migrations and seeders
#    DatabaseSeeder chains everything in the right order: roles/permissions,
#    demo users, settings, currencies, shop catalog (brands/categories/tags/
#    attributes/products/prices/reviews), e-commerce demo data (orders,
#    coupons, shipping, tax, webhooks, stock, blog posts) and marketing demo
#    data (campaigns, contacts, segments, workflows, social posts).
php artisan migrate
php artisan db:seed

#    To seed only a subset, run the individual seeders:
#      php artisan db:seed --class=RolesAndPermissionsSeeder
#      php artisan db:seed --class=ShopProductSeeder
#      php artisan demo:generate            # orders, coupons, shipping, tax, ...
#      php artisan db:seed --class=MarketingDemoSeeder

# 6. Create storage link
php artisan storage:link

# 7. Start development servers (two terminals)
npm run dev     # Vite HMR at localhost:5173
php artisan serve  # Laravel at localhost:8000
```

> Note: the app is served via LocalWP and runs the **production build** (no Vite
> dev server). Verify `public/hot` does not exist — its presence causes
> `ERR_CONNECTION_REFUSED`. Always run `npm run build` after code changes.

## Environment Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `APP_NAME` | `Shop App` | Site name used in emails, page titles, etc. |
| `APP_URL` | `http://localhost` | Must match the deployment URL for proper Vite asset resolution |
| `APP_ENV` | `local` | Set to `production` on live server |
| `APP_DEBUG` | `true` | Set to `false` in production |
| `APP_KEY` | — | Auto-generated by `php artisan key:generate` |
| `DB_CONNECTION` | `sqlite` | `sqlite` for local, `mysql` for production |
| `SESSION_DRIVER` | `database` | Uses `sessions` table; switch to `file` or `redis` for high traffic |
| `CACHE_STORE` | `database` | Uses `cache` table; switch to `redis` for high traffic |
| `QUEUE_CONNECTION` | `database` | Uses `jobs` table; switch to `redis` for async queue workers |
| `MAIL_MAILER` | `log` | `log` writes to `storage/logs/laravel.log`; use `smtp` for real email delivery |
| `DEPLOY_TOKEN` | — | Must match `DEPLOY_TOKEN` GitHub secret for auto-deploy |

## Roles

- **admin** — Full access. Created via `app:create-admin` (cannot register as admin).
- **customer** — Default role for new registrations. Configurable in Settings > Registration.

Roles and permissions are a config catalog (`config/roles.php` in the platform
package, per-app overridable) seeded by `RolesAndPermissionsSeeder`.

## Feature Architecture

Features are self-contained `FeatureProvider`s (slug-based) discovered by the
platform's `FeatureRegistry`. Each provider registers its own routes,
permissions, nav items, dashboard data and frontend pages.

| Feature | Slug | Permissions | Frontend Pages |
| ------- | ---- | ----------- | -------------- |
| Blog    | `posts` | `posts.view`, `posts.create`, `posts.edit`, `posts.delete` | Posts, Categories, Tags |
| Shop    | `shop`  | `shop.view`, `shop.products.manage`, ... | Products, Orders, Cart, Customers, Coupons, Reviews, Storefront |

Frontend page kits are registered in `resources/js/page-config.ts`:
`registerCoreTemplates()` (platform), `registerBlogPages()`, `registerShopPages()`,
spread into a single `basePages` map in the order above.

## Development Commands

```bash
npm run dev              # Vite dev server with HMR
npm run build            # tsc + vite build (production)
php artisan migrate      # Run pending migrations
php artisan test         # Run PHPUnit tests
npm run typecheck        # TypeScript type checking (tsc --noEmit)
vendor/bin/pint          # Laravel Pint (PSR-12 auto-fix)
php artisan permissions:list             # List all permissions
php artisan db:seed --class=RolesAndPermissionsSeeder  # Reset roles/permissions
php artisan app:create-admin             # Bootstrap or update the admin user
```

Other useful commands: `npm run check:ci` (full CI pipeline), `php artisan
test --parallel --compact` (parallel PHPUnit via paratest), `php artisan
demo:generate` (demo e-commerce data), `php artisan marketing:sync-customers`
(sync shop customers into marketing audience), `php artisan
marketing:process-orders` (trigger order-placed workflows).

## Deployment

Deploys automatically on push to `main` via the shared check-first pipeline
(GitHub Actions → Release → token-protected `/deploy/*` endpoints). The unified
GH_TOKEN covers platform/blog/shop-module clones so package updates flow
through `composer update` PRs. See `DEPLOY.md` and `AGENTS.md`.
