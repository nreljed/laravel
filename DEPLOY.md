# Deployment Guide

## How It Works

Every push to `main` triggers a GitHub Actions workflow that:

1. Installs dependencies (composer + npm) and builds assets
2. Generates a production `.env` from secrets
3. Copies `scripts/deploy-cron.php` to `deploy.php` (root-level deploy script)
4. Packages everything into `deploy.zip`
5. Creates a GitHub Release with the ZIP attached

On the server, a cron job runs `deploy.php` every minute. It:

1. Checks GitHub for a newer release
2. Downloads and extracts `deploy.zip` over the current files
3. Restores the existing `.env` (preserving settings between deploys)
4. Runs `migrate`, `config:cache`, `route:cache`, `view:cache`

## Repository Contents

| File | Role |
|------|------|
| `.env` | Generated by workflow during build — contains DB creds, GITHUB_TOKEN |
| `deploy.php` | Copied from `scripts/deploy-cron.php` during build — the cron script |
| `.deploy-lock` | Created by deploy.php to prevent concurrent runs (auto-clears after 10 min) |
| `.deploy-log` | Log file from deploy.php |
| `.deployed-version` | Stores the last deployed tag name |

## First-Time Setup

### 1. GitHub Secrets

| Secret | Value |
|--------|-------|
| `DEPLOY_TOKEN` | Any secure string — matches `config('app.deploy_token')` |
| `GH_TOKEN` | GitHub fine-grained PAT with **Contents: Read** |

How to create the PAT:
- Go to `https://github.com/settings/tokens?type=beta`
- **"Generate new token"** (fine-grained)
- **Repository access**: "Only select repositories" → choose your repo
- **Permissions**: Repository permissions → **Contents: Read**
- Copy the token and add as `GH_TOKEN` secret in repo settings

> Note: `GITHUB_TOKEN` is reserved by GitHub — use `GH_TOKEN` as the secret name.

### 2. First Deploy (Manual)

```bash
# 1. Push to main — workflow creates a Release with deploy.zip
git push origin main

# 2. Download deploy.zip from the resulting Release on GitHub
# 3. Upload deploy.zip to cPanel and extract at public_html/
# 4. Run post-deploy commands (if DB is fresh):
curl "https://yourdomain.com/deploy/cache-clear?token=YOUR_DEPLOY_TOKEN"

# 5. Set up cron job in cPanel (see below)
```

### 3. Cron Job

Add this entry in cPanel **Cron Jobs** (run every 5 minutes):

```
*/5 * * * * /usr/bin/php /home/username/public_html/deploy.php
```

That's it. Every future push will auto-deploy within 5 minutes.

## Troubleshooting

**Site shows 500 after deploy:**
- Check `storage/logs/laravel.log` for errors
- Run `curl "https://yourdomain.com/deploy/cache-clear?token=..."` manually
- Verify `.env` has correct DB credentials

**deploy.php fails to download:**
- Ensure `GITHUB_TOKEN` in `.env` is valid (not expired)
- Check `.deploy-log` for error messages
- Verify the repo URL in deploy.php matches your GitHub repo

**deploy.php not running:**
- Check cron job is active in cPanel
- Verify PHP path: `/usr/bin/php` or `/usr/local/bin/php`
- Test manually: `php /home/username/public_html/deploy.php`

## Files Not Included in deploy.zip

These are never overwritten during deploy because they're either backed up/restored or excluded:

- `.env` — restored from backup
- `.deploy-*` — runtime files (lock, log, version)
- `storage/` — app storage (logs, framework, app)
- `node_modules/` — dev only, not in ZIP
- `vendor/` — included in ZIP (no composer on server)
